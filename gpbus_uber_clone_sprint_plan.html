Sprint 1 Setup & Auth
Semanas 1–2 · Duración: 2 semanas · Objetivo: proyecto corriendo + autenticación completa
US-01 A + B
Configuración del entorno de desarrollo
Como equipo de desarrollo, quiero tener el proyecto React Native CLI configurado con ESLint, Prettier, estructura de carpetas y ramas de GitHub, para que todos los integrantes puedan trabajar de forma consistente desde el inicio.
Criterios: Repo con 3 ramas (main, dev-A, dev-B), RN corriendo en simulador Android/iOS, reglas de linting aplicadas.
US-02 Comp. A
Registro de usuario con validación
Como usuario nuevo, quiero registrarme con nombre completo, celular, género, correo (con validación de @ y dominio) e idioma (ES/EN), para que mi cuenta quede almacenada en Firebase/MongoDB y pueda ingresar a la app.
Criterios: Ningún campo acepta nulos/vacíos. Tab navigation entre secciones de perfil. Foto de perfil cargable.
US-03 Comp. B
Pantalla de Login con navegación Tab
Como usuario registrado, quiero iniciar sesión con correo y contraseña, para que pueda acceder al flujo principal de la app con una navegación Tab estructurada (React Navigation).
Criterios: Autenticación con Firebase Auth. Manejo de errores con mensajes claros. Redirección correcta al Tab principal.
Sprint 2 Mapas & Búsqueda de destino
Semanas 3–4 · Objetivo: usuario ve mapa con su ubicación y busca destinos con Autocomplete
US-04 Comp. A
Visualización de mapa con ubicación actual
Como usuario, quiero ver un mapa interactivo centrado en mi ubicación actual, para que pueda orientarme antes de solicitar un viaje.
Criterios: Google Maps API integrada. Marcador animado en posición del usuario. Solicitud de permisos de ubicación manejada correctamente. Redux guarda estado del mapa.
US-05 Comp. B
Búsqueda de destino con Google Places Autocomplete
Como usuario, quiero escribir un destino y recibir sugerencias en tiempo real, para que encuentre rápidamente el lugar al que quiero ir.
Criterios: Google Places Autocomplete integrado. Sugerencias se actualizan mientras el usuario escribe. Al seleccionar, el mapa centra el destino.
Sprint 3 Solicitud de Viaje & Rutas
Semanas 5–6 · Objetivo: usuario puede ver ruta, elegir tipo de vehículo y ver tarifa estimada
US-06 Comp. A
Cálculo y visualización de ruta óptima
Como usuario, quiero ver la ruta trazada entre mi origen y destino con tiempo y distancia estimados, para que sepa cuánto tardará mi viaje antes de confirmar.
Criterios: Google Directions API + Distance Matrix API. Polyline dibujada en el mapa. ETA y distancia mostrados en card inferior.
US-07 Comp. B
Selección de categoría de vehículo y tarifa estimada
Como usuario, quiero elegir entre Económico, XL y Premium, para que vea la tarifa estimada de cada categoría antes de confirmar mi solicitud.
Criterios: Cards con precio por categoría. Redux guarda selección. Botón de confirmar activo solo cuando hay selección válida.
Sprint 4 Seguimiento, Pagos e Historial
Semanas 7–8 · Objetivo: tracking en tiempo real, pasarela de pagos e historial de viajes
US-08 Comp. A
Seguimiento en tiempo real del conductor
Como pasajero, quiero ver el conductor aproximándose en el mapa con un marcador animado en tiempo real, para que sepa exactamente cuándo llegará.
Criterios: Marcador del conductor actualizado vía Firebase Realtime DB. Animación fluida del marcador. Posición del pasajero también visible.
US-09 Comp. B
Integración de pasarela de pagos (Stripe / Mercado Pago)
Como usuario, quiero pagar mi viaje con tarjeta o Mercado Pago, para que la transacción sea segura y quede registrada.
Criterios: Stripe SDK integrado. Flujo de pago completo (formulario → confirmación → error). Registro del pago en DB asociado al viaje.
US-10 A + B
Historial de viajes con detalles
Como usuario, quiero ver el listado de mis viajes anteriores con costo, fecha y ruta, para que pueda llevar un registro de mis desplazamientos y gastos.
Criterios: Lista paginada desde DB. Cada item muestra origen, destino, fecha, costo. Toque en item muestra detalle completo.
Estructura de ramas
main
Código estable y listo para producción. Solo recibe merges al finalizar cada sprint vía PR revisado.
feature/dev-A
Rama de trabajo del Compañero A (Backend/Maps/Auth). Aquí suben todos los commits del compañero A durante el sprint.
feature/dev-B
Rama de trabajo del Compañero B (UI/Navigation/Payments). Aquí suben todos los commits del compañero B durante el sprint.
Flujo de trabajo por sprint
1
Inicio de sprint: Cada uno hace git pull origin main en su rama para sincronizar.
2
Desarrollo: Commits frecuentes en su propia rama (feature/dev-A o feature/dev-B). Mínimo 1 commit por sesión de trabajo.
3
Fin de sprint: Cada uno abre un Pull Request desde su rama hacia main. El compañero revisa el PR antes del merge.
4
Merge: Se resuelven conflictos localmente, se aprueba el PR y se hace merge a main. Nunca push directo a main.
A
Compañero A — Backend & Maps Lead
Rama: feature/dev-A
  • Sprint 1: Configuración del proyecto RN CLI, estructura de carpetas, configuración de Redux store, integración Firebase/MongoDB (auth + DB)
  • Sprint 2: Google Maps API + permisos de ubicación, marcador del usuario en tiempo real
  • Sprint 3: Google Directions API, Distance Matrix API, polyline en mapa, ETA
  • Sprint 4: Firebase Realtime DB para tracking del conductor, marcador animado del driver
  • Siempre: Lógica de negocio en Redux (actions, reducers, selectors), integración con endpoints de DB, manejo de hooks personalizados (useLocation, useTrip, useAuth)
B
Compañero B — UI/UX & Integrations Lead
Rama: feature/dev-B
  • Sprint 1: Pantallas de Login y Registro, Tab Navigation con React Navigation, validaciones de formularios, foto de perfil
  • Sprint 2: Componente de búsqueda con Google Places Autocomplete, sugerencias en tiempo real, UI de destino
  • Sprint 3: Cards de selección de vehículo (Económico/XL/Premium), UI de tarifa estimada, botón de confirmación
  • Sprint 4: Integración Stripe SDK (UI del formulario de pago), pantalla de historial de viajes, pantalla de detalle de viaje
  • Siempre: Componentes reutilizables, sistema de estilos consistente, i18n (Español/Inglés), manejo de estados de carga y error en UI
Todos los mensajes de commit deben estar en inglés, seguir el formato type(scope): short description y ser descriptivos del cambio.
feat — nueva funcionalidad
feat(auth): add user registration with field validation
feat(maps): integrate Google Maps API with user location marker
feat(trip): add vehicle category selection with fare estimate
fix — corrección de bug
fix(auth): prevent empty email submission on login form
fix(maps): resolve location permission crash on Android 13
refactor — mejora sin cambio de funcionalidad
refactor(redux): split trip reducer into smaller slices
refactor(ui): extract reusable VehicleCard component
chore — configuración / dependencias
chore: add ESLint and Prettier configuration
chore(deps): upgrade react-navigation to v7
docs — documentación
docs: add setup instructions to README
docs(api): document Google Maps integration steps
